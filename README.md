# daily-companion

予定と日記をひとつにまとめ、AI（Claude）が毎朝・毎晩・毎週それを読んで話しかけてくる、自分用の日記アプリです。
授業やゼミの録音から議事録を作る機能もあります。

自分のPCで動かして、PCとiPhoneのブラウザから使っています。日記や録音は外のサーバーに置かず、PCの中だけに保存します。

## できること

- **朝のまとめ**：毎朝7:30に、今日の予定とニュースの要約をスマホに通知する
- **日記**：毎晩22:00に「今日は何した？」と通知する。返信をAIが整理して保存し、日曜には1週間の振り返りレポートを作る
- **予定の登録**：「明日10時からゼミ」と書くと、AIが日時を読み取り、確認してからGoogleカレンダーに入れる
- **議事録**：iPhoneで録音すると、PCが数秒ごとに文字にして、AIが議事録を書き進める。録音を止めると全体を文字起こしし直し、誰が話したかを聞き分けて清書する
- **音声入力**：PCで右Ctrlを押して話すと、カーソルの位置に文字が入る

## 工夫したところ

- **AIに任せる所と、プログラムで決める所を分けた**
  AIに頼むのは、文章の整理・要約・清書だけです。「えーと」などのつなぎ言葉を消す処理や、辞書での言葉の置き換えはプログラムで行い、AIに勝手に書き換えさせないようにしました。
- **失敗しても記録が消えない**
  音声は届いた時点でまず保存するので、文字起こしやAIが途中で失敗しても、あとからやり直せます。データベースは毎朝バックアップして、7日分を残します。
- **本人の機器からしか開けない**
  ログインの仕組みを持たない代わりに、開ける相手をこのPCとTailscale（自分の機器だけをつなぐVPN）に絞りました。よそのWebページから日記を書き換えさせる攻撃（CSRF）なども断ります。スマホの通知には日記の中身を載せません。
- **使うほど文字起こしが正確になる**
  議事録を手で直すと、直した言葉（「田名か」→「田中」）を辞書の候補に出します。辞書に登録した人の名前や授業の用語は、次の録音から文字起こしのヒントとして使います。
- **テストで動きを確かめながら作った**
  テストは46ファイル・約620個あります。

## 使っている技術

| 分野 | 使ったもの |
|---|---|
| 言語 | Python 3.13（パッケージの管理は [uv](https://docs.astral.sh/uv/)） |
| Webの画面 | FastAPI、Jinja2 |
| データベース | SQLite（`data/companion.db`） |
| AI | Claude（`claude -p` をプログラムから呼ぶ） |
| 文字起こし | faster-whisper（PCのGPUで動かす） |
| 話した人の聞き分け | sherpa-onnx |
| 外のサービス | Googleカレンダー（Calendar API）、[ntfy.sh](https://ntfy.sh)（スマホへの通知）、Tailscale |
| 自動で動かす仕組み | Windowsのタスクスケジューラ |

詳しい仕様は [要件定義書](docs/requirements.md) にまとめています。

## 定期的に動くこと

| 時刻 | 動作 |
|---|---|
| 毎朝 07:30 | バックアップ → 予定の同期 → ニュース収集（各5件・ジャンルは同時実行）→ ブリーフィング生成 → Push通知 |
| 毎晩 22:00 | 「今日は何した？」とPush通知。返信した内容をClaudeが構造化して保存 |
| 毎週日曜 21:00 | 1週間分の日記から傾向・やり残し・来週の提案をレポート（日記のない週は作らない） |

| `/mail` | 大学のメールのAI判定結果（要対応・確認・不要）を表で。区分で絞り込める。今日の画面にも「要対応メール」欄が出る（mail-notifier と連携、`MAIL_RESULTS_FILE` を設定） |

## 議事録のしくみ

**録音している間**
- iPhoneで録音すると、PCのWhisper（GPU）が数秒で文字にし、Haikuが議事録を書き進める様子がそのまま画面に出る
- 音声は届いた時点でまず `data/minutes/` に保存するので、文字起こしやAIが失敗しても残る
- マイクはhttpsでしか使えないため、iPhoneからは Tailscale の `https://〜.ts.net/minutes` で開く

**録音を止めたあと**
- 録音全体を正確なモデル（large-v3）で文字起こしし直す
- 声で誰が話したかを聞き分ける（sherpa-onnx・CPU）。録音を始めるときに参加者の名前（例: 自分、田中、佐藤）を入れると、その人数で聞き分けるので精度が上がる。聞き分けのモデルは初めて使うときに `data/models/diarization/` へ自動で落とす
- Sonnet 5.5 が話した人の名前を推測しながら清書して、ノート・文字起こしを保管庫に、録音（m4a）を `RECORDINGS_DIR` に書き出す

**場面ごとの置き場所**

録音を始めるときに場面を選ぶ。場面ごとに見出しと置き場所が変わる。

| 場面 | 置き場所 |
|---|---|
| ゼミ | `MINUTES_DIR`（既定は保管庫の `研究\ゼミ議事録`） |
| 授業 | 選んだ授業のフォルダの `議事録\`（授業の一覧は保管庫の `<学期>\<授業>` から作る） |
| 打ち合わせ | `_授業以外\打ち合わせ` |
| ひとりメモ | 保管庫に出さずアプリの中だけ（日記と同じく手元に置く） |

場面は清書のあとでも会議の画面で変えられ、「清書をやり直す」でノートを新しい場所へ移す。
ひとりメモはアプリを開かずに、iPhoneのショートカットから `/minutes/quick` に送れる（作り方は `docs/ひとりメモのショートカット.md`）。

**辞書**
- 辞書に人の名前や授業の用語を登録すると、Whisperにヒントとして渡してはじめから正しく出やすくし、間違えやすい書き方は文字起こしのあとで置き換える
- 「えーと」「あのー」などのつなぎ言葉も、決めた一覧のものだけを機械的に消す（AIに書き直させない）
- 議事録を「手で直す」で直すと、直した言葉（「田名か」→「田中」）を拾って辞書の画面に候補として出し、本人が「登録する」を押すと辞書に入る（文字起こしを壊しやすい直し＝ひらがなだけ・送り仮名だけの違いは拾わない）

**音声入力**
- PCでは右Ctrlを1回押して話し、もう1回押すとカーソルの位置に文字が入る（`companion.dictation`、ログイン時に `daily-companion-dictation` タスクで起動）
- iPhoneはショートカットから `/dictate` に送って文字をクリップボードに入れる
- どちらも議事録と同じWhisperと辞書を使い、録音は残さない（`docs/音声入力.md`）

## セットアップ

```bash
uv sync
```

```bash
copy .env.example .env
```

`.env` に `NTFY_TOPIC` を記入し、Googleのサービスアカウント鍵を `credentials/service-account.json` に置いたあと、DBを初期化します。

```bash
uv run python -m companion.db.init
```

外部連携が正しく設定できているかを確認します。

```bash
uv run python -m companion.doctor
```

**管理者PowerShell**でタスクスケジューラに登録します。これでWebアプリの常駐と定期ジョブが動き出します。

```bash
powershell -ExecutionPolicy Bypass -File scripts\register_tasks.ps1
```

登録されるタスク:

| タスク | タイミング | 内容 |
|---|---|---|
| `daily-companion-web` | PC起動時 | Webアプリの常駐（落ちたら10秒後に自動再起動） |
| `daily-companion-morning` | 毎日 07:30 | バックアップ → 予定同期 → ニュース → ブリーフィング |
| `daily-companion-evening` | 毎日 22:00 | 日記の催促（記録済みの日は送らない） |
| `daily-companion-weekly` | 毎週日曜 21:00 | 週次の振り返り |

いずれもS4Uログオンなので、Windowsにログインしていなくても動きます。
PCが落ちて実行時刻を逃した場合は、起動後に追いかけて実行されます。

手動で起動・停止・実行することもできます。

```bash
uv run python -m companion.jobs.morning_brief
```

```bash
powershell -ExecutionPolicy Bypass -File scripts\stop_web.ps1
```

### コードを変更したあとの再起動

常駐中のWebアプリは古いコードを読み込んだままなので、変更を反映するには再起動します。
**管理者PowerShell**で実行してください。S4Uタスクのプロセスはセッション0で動くため、
通常の権限では停止できず `Access is denied` になります。

```bash
powershell -ExecutionPolicy Bypass -File scripts\restart_web.ps1
```

## ニュースのジャンル

`.env` の `NEWS_TOPICS` で選びます。ジャンルは同時に収集されるので、
所要時間はジャンル数ではなく一番遅いジャンルで決まります（4ジャンル×5件で約5分）。

ただし `jobs/news_digest.py` の `MAX_CONCURRENT`（現在4）を超えると
2巡目が発生し、所要時間がほぼ倍になります。ジャンルを5つ以上にするときは
この値も上げてください。

| ジャンル | 内容 |
|---|---|
| `ai_tech` | AI・IT技術 |
| `job_hunting` | 就活・業界動向 |
| `social` | 就活の実践知・体験記（ES・面接・インターンの具体的な記録） |
| `economy` | 経済・市場（金融政策、為替・株式、景気指標、決算） |
| `domestic` | 国内一般ニュース |
| `world` | 海外・国際情勢 |

`social` は当初Xを主な情報源にする想定でしたが、Xはログインなしではほとんど読めず、
実際に集まるのは note・Qiita・個人ブログの体験記でした。名前は実態に合わせています。

## バックアップ

朝のジョブが毎日 `data/backups/companion-YYYYMMDD.db` を作り、7世代を保ちます。
SQLiteのオンラインバックアップAPIを使うので、書き込み中でも取りこぼしません。

戻すときは、Webアプリを止めてからファイルを差し替えます。

```bash
copy data\backups\companion-20260808.db data\companion.db
```
